# Methods and interpretation

GSE276099 was inspected at the GEO series and six sample records. The versioned `sample_manifest.tsv` maps C1–C3 to GSM8491080–GSM8491082 and T1–T3 to GSM8491083–GSM8491085. The common protocol says 150 µM β-caryophyllene or ethanol for 24 h, while the individual treatment fields read 150, 151, and 152 µM by replicate. This project preserves the inconsistency and does not infer actual dosing.

The notebook pins the downloaded supplementary CSV by SHA-256. The analysis excludes rows without a numeric `gene_id` or a complete six-column value. Exactly 20 excluded rows have long gene-set-like IDs and six blank cells; 17,034 numeric-gene rows remain. Their retained values are nonnegative but 75,830 of 102,204 entries are fractional, compatible with processed RSEM-style expected counts. No values are rounded to integer counts.

Each retained sample column is scaled to counts per million (CPM) using its retained-row total. Correlations use log1p(CPM). For descriptive effects, a gene enters when the maximum of the two arm-mean CPMs is at least 1. The reported log2 ratio is `log2((mean_treated_CPM + pseudocount)/(mean_control_CPM + pseudocount))` for pseudocounts 0.1 and 1.0. These thresholds have no p-values and are not a differential-expression analysis. The PGF, NR4A1, CSF1R, ARTN, and CACNA1E values are direct lookups from this filtered matrix, not pathway activity estimates or target-binding assays.

The [paper](https://doi.org/10.3389/fphar.2024.1492670) reports 433 protein-coding DEGs and experiments involving PGF overexpression. Those findings remain source-reported. Resolving the dosing fields and reprocessing original reads with a pinned annotation would be needed before independent inferential comparison. Additional cell contexts and genetic perturbations would be needed to assess context or target dependence.

## Raw-read reanalysis input

The [raw-run manifest](raw_run_manifest.tsv) maps each GEO sample and matrix column through its BioSample and experiment to one ENA run and one single-end FASTQ. Its six compressed FASTQs total 7,453,487,888 bytes. File lengths and MD5 values came from the [ENA run report](https://www.ebi.ac.uk/ena/portal/api/filereport?accession=PRJNA1154682&result=read_run&fields=run_accession,sample_accession,experiment_accession,fastq_ftp,fastq_bytes,fastq_md5&format=tsv), and the GEO-to-BioSample/experiment links came from the [GEO family SOFT record](https://ftp.ncbi.nlm.nih.gov/geo/series/GSE276nnn/GSE276099/soft/GSE276099_family.soft.gz), retrieved 2026-10-26. These are source metadata, not hashes verified from downloaded reads. The six SRA archives and derived FASTQs were downloaded and verified locally on 2026-10-26, with per-run read counts and SHA-256 values in the versioned [conversion receipt](results/raw_counts/conversion_receipt.json). The executed notebook and report still describe only the deposited fractional matrix; the raw reads have not yet been aligned or quantified.

The [NCBI SRA manifest](sra_run_manifest.tsv) is the active retrieval route. It records the six normalized SRA objects, sizes, and MD5 values returned by the [NCBI SRA Data Locator](https://locate.ncbi.nlm.nih.gov/sdl/2/retrieve?acc=SRR30495544&meta-only=yes). [fetch_sra_inputs.py](fetch_sra_inputs.py) verifies those objects, and [convert_sra_to_fastq.py](convert_sra_to_fastq.py) uses NCBI fasterq-dump and pigz 2.8 (`-n -1 -p 4`) to produce FASTQs with conversion receipts and read-count checks. The pigz command omits filename and timestamp from the gzip header, and its version and settings are recorded in each receipt. [fetch_raw_inputs.py](fetch_raw_inputs.py) separately verifies the GENCODE human release 48 primary-assembly FASTA/GTF against [GENCODE MD5SUMS](https://ftp.ebi.ac.uk/pub/databases/gencode/Gencode_human/release_48/MD5SUMS); its slower ENA FASTQ route remains an alternative source cross-check. [reprocess_star_counts.py](reprocess_star_counts.py) then builds a STAR 2.7.11b index with suffix-array sparsity 8, a 12 GB index-generation memory cap, and a 49-base splice-junction overhang for the 50-base single-end reads and writes unstranded integer gene counts plus per-library mapping QC. Large input/index files remain outside Git. These scripts do not establish a biological result until the processing and notebook receipts exist and QC has been reviewed.

```sh
python research/hepg2-bcp-rsem/fetch_raw_inputs.py reference
python research/hepg2-bcp-rsem/fetch_sra_inputs.py --workers 6
python research/hepg2-bcp-rsem/convert_sra_to_fastq.py
python research/hepg2-bcp-rsem/build_star_patched.py
python research/hepg2-bcp-rsem/reprocess_star_counts.py
```

The STAR build pins the 2.7.11b source archive by SHA256 and initializes `transform.outQuant` in the source before compilation. This fixes the [upstream `/geneInfo.tab` GeneCounts bug](https://github.com/alexdobin/STAR/issues/1953) observed on this Apple Silicon host. The processing receipt records the patched binary SHA256. On macOS, the build requires Homebrew GCC 15; on Linux it uses GCC and make.

After mapping QC is reviewed, the [raw-count notebook](../../notebooks/terputer-hepg2-bcp-raw-counts.ipynb) reads the checksum-pinned compressed count and annotation tables, assigns treatment from the GEO sample manifest pinned in the processing receipt, and uses PyDESeq2 0.5.4 for a prespecified treatment-only negative-binomial model. The compressed tables fit the report publisher's per-file limit and retain deterministic gzip headers. It requires a separate Python 3.13 environment, reproducible from [requirements-raw-counts.lock.txt](../../requirements-raw-counts.lock.txt). The notebook is intentionally unexecuted while alignment is incomplete; no count-based differential-expression claim has been made.

When all six libraries have passed mapping QC, run `python research/hepg2-bcp-rsem/run_raw_count_notebook.py` from the repository root in that environment, or launch the same script with Terputer's `start_research_job` tool and poll `get_research_job`. The wrapper declares the processing receipt, count tables, QC, manifests, and analysis script as notebook inputs; it declares all analysis tables and the QC figure as outputs. The resulting `research/execution-receipts/terputer-hepg2-bcp-raw-counts.json` binds them for report generation and curated gene-effect export. No inferential claim should be added to the white paper before that execution receipt and its QC are reviewed.
